## What this revision does
Generates the order receipt/invoice PDF (`routes/order/receipt.js`) with `pdfmake` instead of `html-pdf` (PhantomJS), and removes `html-pdf` and `phantomjs-prebuilt`.

## Why this revision exists
`html-pdf` is deprecated and depends on PhantomJS, which is dead and needs a binary download at install time.

## What changed
- New `routes/order/receipt_document.js`: pure functions that build the pdfmake document definition (`buildReceipt`) and the receipt data (`productRows`, `firstPaymentRows`, `firstPaymentTotals`, `customerLines`, `invoiceLines`). The old `getName`, `getDateTime`, `isPicked` helpers moved there.
- `routes/order/receipt.js` shrank from 933 to ~225 lines: the ~650 lines of HTML string building (`generatePDF`, `generateFirstPDF`, `generateProductList`, `generateCustomerDetails`, `generateInvoiceDetails`) are gone. Kept `getStoreInfo`, `getTotalPrice`; `generateBarcode` now resolves a PNG data URI; new `getLogo` downloads the shop logo as a data URI and falls back to the shop name; new `generateReceipt` wires them together. The handler renders with `pdfmake.createPdf(doc).getBuffer()` and sends it as `application/pdf`.
- `package.json`: added `pdfmake` 0.3; removed `html-pdf` (and with it `phantomjs-prebuilt`); `allowScripts` is empty again. pdfmake has no install scripts.
- Tests: `tests/receipt_document.test.js`.

## Implementation decisions
- Same content as before: header (logo or shop name, invoice details, customer, barcode), product table (Product / Aantal / btw / Prijs excl. / Prijs incl. / Totaal), discount, VAT, excl. VAT and grand total rows, footer with shop details, A4 portrait, 0.5in margins. Pricing rules are the old ones (deposit, discount, picked vs ordered amount, first payment = personal shopper + delivery fee at 21%).
- pdfmake is locked down: URL access denied (logo is fetched by us), local access only for the bundled Roboto fonts. Font: Roboto (bundled) instead of Arial.
- The footer now repeats on every page (old layout pinned it absolutely to the first page).
- Dropped dead code: the `delivery === true` branch called an undefined `firstPaymentPDF()`; `generatePDF` was never called with it.
- Null-safe access on `invoice_order_information` (old code threw on `invoice_order_information.street` when it was null).

## Architectural decisions
Presentation (document definition) is separated from data access (models, store info, logo fetch), so the receipt layout can be tested without a database.

## Tests added
`tests/receipt_document.test.js` (6 tests): ordered vs picked quantity, excl-vat/discount/deposit maths, first-payment rows and totals, customer/invoice lines, document contents for a normal and a first-payment receipt, and that both render to a valid PDF (`%PDF-`) with pdfmake.

## Tests executed
- `npm test`: 11/11 pass. `npm ls` clean; no unreviewed install scripts; scratch copy loads all route/model files.
- Scratch end-to-end (not committed): the real `receipt.js` route in an express app with `Order.findOne` and `Shop.findAll` stubbed and a local logo server: both `?first=1` and normal requests return 200 `application/pdf` with a valid PDF (logo downloaded, barcode embedded).
- Rendered 40-product and first-payment sample PDFs (3 pages / 1 page).
- NOT done: a visual check. No PDF rasteriser is available here, so the layout has not been looked at. Not run against the real DB.

## Known limitations
- The layout is not pixel-identical to the old HTML (fonts, spacing). **Please open one normal and one `?first=1` receipt and check them.**
- SVG/WebP logos are not supported by pdfmake; the shop name is shown instead.

## Future work discovered
- `getTotalPrice` and the new `productRows` repeat the same pricing rules; they could share one function.
- `getTotalPrice` logs the whole order/product list with `console.log` on every receipt.
- Hardcoded `Cryptr('myTotalySecretKey')` (security revision) and an unused `cryptr` in receipt.js.

## Summary
Receipts are generated by pdfmake; PhantomJS is gone and the receipt code is a third of its size and unit tested.
